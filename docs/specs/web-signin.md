## Verified facts about `agy` 1.5.16 sign-in with a fresh HOME (24/11/2026)
- `HOME=<slotDir> agy` (no args) needs a real TTY. It shows "Welcome to the Antigravity CLI. You are currently not signed in." then a menu "Select login method:" with "> 1. Google OAuth" / "2. Use a Google Cloud project". Pressing Enter (`\r`) picks Google OAuth.
- It then runs `open <URL>` found via PATH (a PATH shim named `open` receives the URL as argv[1] and stops the real browser from opening). The URL is `https://accounts.google.com/o/oauth2/auth?...&redirect_uri=https%3A%2F%2Fantigravity.google%2Foauth-callback&...&state=...` (PKCE). The screen also prints the URL and "If you aren't automatically redirected, paste the authorization code below:", with an input field. Writing the code followed by `\r` into the TTY submits it.
- With HOME overridden, macOS `security` finds no login keychain (verified), so the slot's token cannot overwrite the default account's keychain item (svce "gemini", acct "antigravity"); agy falls back to file storage in the slot HOME. Never read those files.

## Hub
1. `apps/hub-daemon/scripts/pty-bridge.py` (python3 stdlib only): `pty-bridge.py <cwd> -- <cmd...>`, run the command in a pty (160x50), copy pty output to stdout raw and stdin to the pty; exit with the child's exit code; kill the child on SIGTERM.
2. `src/signin.ts` `SignInManager` (one active session per slot):
   - `start(slotId)`: refuse the default slot (already signed in) unless `force`; create a temp shim dir with an executable `open` (and `xdg-open`) that appends argv[1] to `<shimDir>/url.txt`; spawn `python3 pty-bridge.py <slotDir> -- <AGY_BIN>` with env HOME=slotDir, PATH=shimDir:PATH, TERM=xterm-256color. Strip ANSI from output into a rolling 20 KB buffer (memory only, never written to logs). When the buffer contains "Select login method", write `\r` once. Wait until url.txt has a URL (or parse an `https://accounts.google.com/...` URL from the screen, joining wrapped lines) -> state `awaiting_user` with `authUrl`. Every 5 s while awaiting, run the accounts `check` for that slot in the background (separate process; `agy models`); when it succeeds -> state `completed`, kill the pty and refresh the slot (email/models/quota), broadcast. Exit before success -> `failed` with the last 5 sanitized screen lines. Timeout 5 min -> `timeout` + kill. Sessions are kept in memory only.
   - `submitCode(slotId, code)`: validate 10..2048 chars, no whitespace or newlines; write code + `\r` to the pty; state `verifying`.
   - `cancel(slotId)`: kill and clean up the shim dir -> `cancelled`.
   - Redaction: anything logged or broadcast has `state`, `code`, `code_challenge`, `nonce`, `access_token`, `refresh_token`, `id_token` query values replaced with `<redacted>`, EXCEPT `authUrl` returned to the UI (it needs the full URL; it is single-use PKCE). Never log `authUrl` or submitted codes.
3. Routes: `POST /api/accounts/slots/:id/signin/start` -> `SignInSession`; `POST .../signin/code {code}`; `POST .../signin/cancel`; `GET .../signin` -> session or `{session:null}`. `SignInSession = { slotId, state: "starting"|"awaiting_user"|"verifying"|"completed"|"failed"|"timeout"|"cancelled", authUrl?: string, message?: string, startedAt, updatedAt, expiresAt }`. WS `{type:"signin", session}` (authUrl included only for the WS clients; never in the log). The old `/signin` (command) endpoint stays.
4. `--verify`: use a stub agy (AGY_BIN) script that prints the menu, waits for Enter, runs `open "https://accounts.google.com/o/oauth2/auth?client_id=x&state=SECRET&redirect_uri=https%3A%2F%2Fantigravity.google%2Foauth-callback"`, then waits for a line; on code "GOODCODE" it touches a marker file in $HOME so the stub's `models` reports signed in. Assert start -> awaiting_user with the URL captured, submitCode -> completed + slot status ready, cancel path, timeout path (short override via env SIGNIN_TIMEOUT_MS), and that the hub log output never contains "SECRET" or "GOODCODE".
